\chapter{Procedure de deploiement}

\section{Prerequis}

\begin{itemize}
    \item Compte AWS Learner Lab actif
    \item CLI AWS, Terraform, Ansible et Docker installes localement
    \item Repository GitHub avec les secrets configures
    \item Paire de cles SSH (key pair) creee dans la console AWS
\end{itemize}

\section{Etape 1 --- Initialisation des credentials}

\begin{lstlisting}[language=bash,caption={Rotation des cles Learner Lab}]
# Executer le script de rotation
./scripts/update-aws-keys.sh

# Verifier l'acces (doit retourner le compte 459624991030)
aws sts get-caller-identity
# {
#   "Account": "459624991030",
#   "Arn": "arn:aws:sts::459624991030:assumed-role/...",
#   "UserId": "..."
# }
\end{lstlisting}

\textbf{Important~:} Les credentials Learner Lab (compte \texttt{459624991030},
region \texttt{us-east-1}) expirent toutes les \~{}4 heures.
Le script met a jour \texttt{\~{}/.aws/credentials} et les GitHub Secrets
du depot \texttt{Michael-Rousseau/devSecOps}.

\section{Etape 2 --- Bootstrap Terraform}

\begin{lstlisting}[language=bash,caption={Creation du bucket d'etat}]
cd terraform/bootstrap
terraform init
terraform apply
\end{lstlisting}

Cette etape cree le bucket S3 et la table DynamoDB pour le state Terraform.
Elle n'est executee qu'une seule fois.

\section{Etape 3 --- Deploiement de l'infrastructure}

\begin{lstlisting}[language=bash,caption={Deploiement complet}]
cd terraform/environments/dev
terraform init
terraform plan -var="db_password=<MOT_DE_PASSE>" \
               -var="nasa_api_key=<CLE_NASA>" \
               -var="ssh_key_name=<NOM_KEY_PAIR>"
terraform apply
\end{lstlisting}

\section{Etape 4 --- Configuration Ansible}

\begin{lstlisting}[language=bash,caption={Execution d'Ansible}]
cd ansible
# Mettre a jour l'IP du bastion (35.173.122.117)
# dans la config SSH et l'inventaire
ansible-playbook playbooks/site.yml
\end{lstlisting}

\section{Etape 5 --- Premier deploiement applicatif}

\begin{lstlisting}[language=bash,caption={Build et push de l'image Docker}]
# Backend --- Build et push vers ECR
cd backend
aws ecr get-login-password --region us-east-1 | docker login \
  --username AWS --password-stdin \
  459624991030.dkr.ecr.us-east-1.amazonaws.com

docker build -t \
  459624991030.dkr.ecr.us-east-1.amazonaws.com/deus-dashboard-backend:latest .
docker push \
  459624991030.dkr.ecr.us-east-1.amazonaws.com/deus-dashboard-backend:latest

# Forcer le redeploiement du service ECS
aws ecs update-service --cluster deus-dashboard-dev \
  --service deus-dashboard-backend --force-new-deployment \
  --region us-east-1

# Frontend --- Build et deploiement S3
cd ..
npm run build
aws s3 sync dist/DEUS_Dashboard/browser/ \
  s3://deus-dashboard-frontend-dev --delete
\end{lstlisting}

\section{Etape 6 --- Verification}

\begin{enumerate}
    \item Acceder au frontend S3~:\\
        \texttt{http://deus-dashboard-frontend-dev.s3-website-us-east-1.amazonaws.com}\\
        L'application Angular doit s'afficher.
    \item Verifier le backend via l'ALB~:\\
        \texttt{http://deus-dashboard-alb-1071352964.us-east-1.elb.amazonaws.com/api/health}
    \item Verifier que l'APOD se charge (appel via le backend)
    \item Tester la liste des evenements naturels
    \item Consulter le dashboard Grafana~: \texttt{http://34.207.159.92:3000}
    \item Verifier les metriques Prometheus~: \texttt{http://34.207.159.92:9090}
    \item Verifier les logs dans le groupe CloudWatch
        \texttt{/ecs/deus-dashboard-backend}
\end{enumerate}
