\chapter{Terraform --- Infrastructure as Code}

\section{Presentation}

Terraform est utilise pour provisionner l'ensemble de l'infrastructure AWS de maniere
declarative et reproductible. La configuration est organisee en modules reutilisables.

\section{Gestion de l'etat}

L'etat Terraform est stocke dans un bucket S3 avec verrouillage DynamoDB~:

\begin{lstlisting}[language=bash,caption={Configuration du backend S3}]
terraform {
  backend "s3" {
    bucket         = "deus-dashboard-tfstate"
    key            = "dev/terraform.tfstate"
    region         = "us-east-1"
    dynamodb_table = "deus-dashboard-tf-locks"
    encrypt        = true
  }
}
\end{lstlisting}

Ce mecanisme garantit~:
\begin{itemize}
    \item Le versionnement de l'etat (historique des changements)
    \item Le verrouillage concurrent (un seul \texttt{apply} a la fois)
    \item Le chiffrement au repos
\end{itemize}

\section{Graphe de dependances}

Les modules sont lies par leurs outputs/inputs~:

\begin{lstlisting}[language={},caption={Ordre de deploiement}]
VPC (base)
  |-- Bastion, ECR, S3, DynamoDB (parallele)
  |-- IAM (LabRole pre-existant, reference par data source)
  |-- RDS (apres VPC, Bastion)
  |-- SSM (apres RDS, DynamoDB)
  |-- ECS (apres tout)
  |-- Monitoring (apres ECS, RDS)
\end{lstlisting}

\section{Modules generiques et injection de variables}

Les modules de \texttt{terraform/modules} sont \emph{agnostiques de
l'environnement}~: aucune valeur specifique (type d'instance, CIDR, version
de moteur, seuils d'alarme, adresse e-mail\ldots) n'y est codee en dur.
Chaque parametre est une variable documentee, avec une valeur par defaut
generique lorsque c'est sans risque, ou \emph{sans} valeur par defaut
lorsqu'une injection explicite est preferable (ex. \texttt{db\_name},
dont le changement detruirait l'instance RDS).

La couche environnement (\texttt{terraform/environments/dev}) compose les
modules et injecte \emph{toutes} les valeurs~:
\begin{itemize}
    \item valeurs non sensibles dans \texttt{terraform.tfvars} (versionne)~;
    \item secrets via variables d'environnement \texttt{TF\_VAR\_db\_password}
        et \texttt{TF\_VAR\_nasa\_api\_key} (jamais commites).
\end{itemize}

Cette separation permettrait de creer un environnement \texttt{prod}
en dupliquant uniquement la couche environnement (autre \texttt{tfvars}~:
\texttt{rds\_multi\_az = true}, instances plus grandes, CIDR distincts),
sans toucher aux modules.

\section{Adaptations pour AWS Learner Lab}

L'environnement AWS Academy Learner Lab impose plusieurs contraintes qui ont
necessite des adaptations de la configuration Terraform~:

\begin{table}[H]
    \centering
    \begin{tabularx}{\textwidth}{lXX}
        \toprule
        \textbf{Contrainte} & \textbf{Probleme} & \textbf{Solution adoptee} \\
        \midrule
        Creation de roles IAM & \texttt{iam:CreateRole} non autorise & Utilisation des roles
            pre-existants \texttt{LabRole} et \texttt{LabInstanceProfile} via
            \texttt{data} sources Terraform \\
        CloudFront OAC & Impossible de creer des distributions CloudFront
            avec OAC & Hebergement statique S3 avec ACLs publiques
            (\texttt{aws\_s3\_bucket\_public\_access\_block} desactive) \\
        PostgreSQL 16.4 & Version non disponible dans le catalogue RDS
            Learner Lab & Utilisation de PostgreSQL 16.14
            (\texttt{engine\_version = "16.14"}) \\
        Expiration des credentials & Les cles AWS expirent toutes les \~{}4 heures &
            Script de rotation \texttt{scripts/update-aws-keys.sh} \\
        Federation OIDC & Impossible de configurer un provider OIDC pour
            GitHub Actions & Cles statiques stockees dans les GitHub Secrets,
            renouvelees manuellement \\
        \bottomrule
    \end{tabularx}
    \caption{Adaptations pour l'environnement Learner Lab}
\end{table}

\subsection{Exemple --- Reference au LabRole}

Au lieu de creer des roles IAM personnalises, la configuration utilise
des \texttt{data} sources pour referencer les roles pre-existants~:

\begin{lstlisting}[language=bash,caption={Reference au LabRole dans Terraform}]
data "aws_iam_role" "lab_role" {
  name = "LabRole"
}

data "aws_iam_instance_profile" "lab_profile" {
  name = "LabInstanceProfile"
}

# Utilisation dans la Task Definition ECS
resource "aws_ecs_task_definition" "backend" {
  execution_role_arn = data.aws_iam_role.lab_role.arn
  task_role_arn      = data.aws_iam_role.lab_role.arn
  # ...
}
\end{lstlisting}

Cette approche evite les erreurs \texttt{AccessDenied} tout en conservant
les permissions necessaires (le \texttt{LabRole} dispose de permissions
suffisantes pour ECS, ECR, SSM, CloudWatch et DynamoDB).
