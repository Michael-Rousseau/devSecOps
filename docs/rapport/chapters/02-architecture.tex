\section{Composants}

\subsection{Frontend --- S3 Static Website Hosting}

L'application Angular est compilee en fichiers statiques et deployee sur le bucket S3
\texttt{deus-dashboard-frontend-dev}. Le bucket est configure en mode
\emph{Static Website Hosting} avec~:
\begin{itemize}
    \item ACLs publiques pour permettre l'acces en lecture
    \item Document d'index \texttt{index.html}
    \item Gestion du routage SPA (document d'erreur redirige vers \texttt{index.html})
\end{itemize}

\textbf{Note~:} L'architecture initiale prevoyait CloudFront avec Origin Access Control (OAC)
comme CDN. Cependant, l'environnement AWS Learner Lab ne permet pas la creation
de distributions CloudFront avec OAC (permissions IAM insuffisantes). La solution
adoptee est l'hebergement statique S3 direct, qui reste fonctionnel pour un projet
pedagogique.

\subsection{Backend --- ECS (EC2 Launch Type)}

Le backend Express est conteneurise et deploye sur ECS avec le type de lancement EC2.
Ce choix, plutot que Fargate, permet de~:
\begin{itemize}
    \item Configurer les instances EC2 avec Ansible
    \item Demontrer la gestion de l'Auto Scaling Group
    \item Installer des agents de monitoring personnalises
\end{itemize}

Un Application Load Balancer (ALB) distribue le trafic vers les conteneurs
via le port mapping dynamique.

\subsection{Bases de donnees}

\begin{description}
    \item[RDS PostgreSQL] Base relationnelle pour les favoris utilisateur et l'historique
        de recherche. Instance \texttt{db.t3.micro} en single-AZ.
    \item[DynamoDB] Cache des reponses API NASA avec TTL automatique.
        Mode de facturation PAY\_PER\_REQUEST.
\end{description}
